# Prior-Art Memo: HLA-Verify and HLA-Bench

*Prepared 2026-09-10 for Brelsford Software LLC (Jason Brelsford). Research memo, not legal advice - see disclaimer at the end.*

## Executive summary

- **Element 1** (deterministic, release-pinned allele-name verification against IPD-IMGT/HLA, served as API + MCP tool): **none found** that is both release-pinned and served as an MCP tool for agents; closest neighbors are py-ard (a reduction library, not a verifier) and the IPD-IMGT/HLA Allele Query Form (a lookup form, not a fabrication classifier).
- **Element 2** (executable-oracle LLM benchmark for HLA nomenclature/matching, regenerated per quarterly release for contamination resistance): **none found** specific to HLA or immunogenetics; general contamination-resistant benchmark methodology exists (adjacent) but no domain instance.
- **Element 3** (executable donor-recipient matching rules engine as a verification gate): **adjacent** - DonorCheck (Univ. of Minnesota) and several patents (Nant/Nantomics, Pirche/UMC Utrecht) encode matching/typing logic, but none is framed as a gate on LLM output, and none of the published tools implement GvH/HvG-direction plus null-allele-trap plus resolution-insufficient "potential" verdicts as one auditable rule set.
- **Element 4** (gating/verifying LLM output in clinical genomics/immunogenetics generally): **adjacent, not on-point** - general-purpose hallucination-detection patents (Adobe, Intuit, C3 AI) and literature (Med-HALT, MedHallu) exist, and general biomedical-ontology-grounding papers exist, but none targets structured genomic/immunogenetic identifiers such as HLA allele names specifically.

## What appears novel

Across patents, commercial/open-source software, and literature, no prior item combines: (a) deterministic classification of an arbitrary free-text or LLM-generated token against a **specific, cited, release-pinned** IPD-IMGT/HLA database snapshot into the five-way verdict (valid / deleted-with-successor / legacy / fabricated-group / hallucinated), (b) delivered simultaneously as a public REST API and as an **MCP tool** so any LLM agent can self-check before presenting output, and (c) an accompanying benchmark that is mechanically **regenerated from each new quarterly release** so that post-cutoff tasks cannot have been memorized. The closest single tool to element 1 is py-ard, which this repo's own concordance report (`docs/pyard-concordance.md`) shows explicitly diverges on exactly this point: py-ard reduces a fabricated allele to a plausible real one rather than flagging it, because reduction and verification are different jobs. The closest tool to element 3 is DonorCheck, which validates human data entry against a source report rather than gating a generative model's output, and does not encode GvH/HvG directionality or an executable "potential"-verdict rule for unresolvable typing. The closest benchmarks to element 2 are Med-HALT/MedHallu/MedHallBench, none of which touch HLA, immunogenetics, or nomenclature fabrication, and none of which are regenerated from a versioned upstream database. No patent was found claiming any of elements 1-4 as such; the nearest patent-space neighbors are general enterprise hallucination-detection filings (C3 AI, Intuit, Adobe) that are domain-agnostic and reference-corpus-based rather than fixed-grammar/ontology-based.
